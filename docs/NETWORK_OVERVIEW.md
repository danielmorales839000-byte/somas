# SOMAS v5.2 — Network overview on Dashboard

The existing light-mode dashboard now includes a blockchain-style Network overview above the animated organization studio. It is a concept display, not a deployed chain or token market.

The default view now runs the random simulation described in [Network simulation](NETWORK_SIMULATION.md). The fixed counts below describe Source snapshot mode.

## Displayed information

- 1 SOMAS = one independent AI organization with a Manager and specialist team. No token price or exchange rate is defined.
- 10,001 synthetic organizations and 80,010 modeled agents.
- Approved claim counts for 1 hour, 24 hours, 3 days, 7 days, rolling 30 days and all time. Period buttons update metrics, the outcome split and the chart; all six totals remain visible together.
- Twelve equal-duration chart bins for the selected interval.
- Recent source claims and four recent illustrative hash-chain blocks, with source heights and shortened hashes.
- Eight participant status counts from the supplied manifest.

## Metric definition and source time

Approved work claims count distinct synthetic claim records with decision `approved`. This is not a count of audited completed tasks: the supplied claim-to-task organization links are inconsistent. No joins or blockchain finality are invented.

The source watermark is 2026-10-25T12:00:00.001Z, one millisecond after the latest claim/block timestamp. Every range is start-inclusive and end-exclusive. Windows are anchored to this watermark, not to the visitor's clock. UTC timestamps are shown explicitly. The one-hour figure is computed from exact claim timestamps, not an estimate from daily totals.

| Range | Approved | Rejected | Pending |
| --- | ---: | ---: | ---: |
| 1 hour | 79 | 0 | 0 |
| 24 hours | 333 | 0 | 0 |
| 3 days | 1,001 | 0 | 0 |
| 7 days | 1,669 | 334 | 334 |
| 30 days | 6,003 | 2,001 | 2,001 |
| All time | 9,000 | 3,000 | 3,000 |

`public/exhibition/dataset/network-overview.json` is generated by `node scripts/build-network-overview.mjs` from all organization claim files, block files and the manifest. The checked-in file means visitors fetch one small aggregate file rather than 10,001 organization files. Rebuild it only when replacing the synthetic corpus.

## Verification

15 relevant tests passed. Tests independently scan all 15,000 source claims, verify uniqueness, recompute every exact time window, reconcile each outcome and chart-bin sum, verify participant-state totals, and reject malformed aggregates. Browser tests selected every period and observed 79 / 333 / 1,001 / 1,669 / 6,003 / 9,000 approved claims. Mobile 30-day selection returned 6,003. Phone usable width and document scroll width both measured 375px; Network panel width was 341px without horizontal overflow. Changed modules pass syntax checks. Backend code was not changed for this release; its full suite was not rerun for this UI addition.
